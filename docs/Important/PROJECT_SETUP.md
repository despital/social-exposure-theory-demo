## 2. Setup & Installation

### Prerequisites
- Node.js v14+, npm
- Python 3.7+ (data export scripts)
- R 4.0+ (optional, for R-based export)

### Installation

```bash
git clone <repo-url>
cd social-exposure-theory
npm install
```

**Verify stimuli** — `stimuli/faces/` must contain 320 images:
- 80 base faces: `face_000_red.png` through `face_039_blue.png`
- 240 novel faces: `face_n001_red.png` through `face_n120_blue.png`

**To regenerate colored faces** from FaceGen sources:

```bash
# Base faces (Phase 1)
python scripts/generate_colored_faces.py stimuli/fg_faces stimuli/faces

# Novel faces (Phase 2)
python scripts/generate_colored_faces.py stimuli/fg_faces/novel_faces stimuli/faces
```

## 3. Development

### Local Server

```bash
npm start  # Dev server with hot reload at http://localhost:8080
```

| Mode | URL |
|---|---|
| Full experiment | `http://localhost:8080` |
| Demo (5 trials/phase) | `http://localhost:8080?demo=true` |
| Debug | `http://localhost:8080?debug=true` |

### URL Parameters

| Parameter | Values | Description |
|---|---|---|
| `c` | 3-char code (e.g., `RXE`) | Condition assignment (see RESEARCH_DESIGN.md §2) |
| `debug` | `true` | Enable debug mode |
| `section` | `consent`, `demographics`, `phase1`, `phase2`, `phase3`, `endsurvey`, `end` | Jump to section (debug only) |
| `autoclick` | `true` | Auto-advance through trials (debug only) |
| `demo` | `true` | Load demo version |
| `PROLIFIC_PID`, `STUDY_ID`, `SESSION_ID` | string | Prolific participant identifiers |

**Prolific URL format:**
```
https://despital.github.io/social-exposure-theory-demo/?c=EXE&PROLIFIC_PID={{%PROLIFIC_PID%}}&STUDY_ID={{%STUDY_ID%}}&SESSION_ID={{%SESSION_ID%}}
```

### Debug Mode

Activated via `?debug=true`. All settings configurable in `config.js → DEBUG_MODE`:

| Setting | Default | Effect |
|---|---|---|
| `SKIP_CONSENT` | `true` | Skip consent form |
| `SKIP_DEMOGRAPHICS` | `true` | Skip demographics survey |
| `REDUCE_PHASE1_TRIALS` | `true` | 1 exposure instead of 12 (10 trials total) |
| `REDUCE_PHASE2_TRIALS` | `true` | 6 faces (3 red + 3 blue) instead of 20 |
| `REDUCE_PHASE3_TRIALS` | `true` | 5 faces instead of 40 |
| `ENABLE_AUTOCLICK` | `false` | Override with `?autoclick=true` in URL |

**Section jumping** (test one phase in isolation):

```
?debug=true&section=phase1      # Phase 1 only
?debug=true&section=phase2      # Phase 2 only
?debug=true&section=phase3      # Phase 3 only
?debug=true&section=endsurvey   # End surveys only
?debug=true&section=end         # Skip to completion screen
```

## 4. Configuration

All parameters are centralized in `src/utils/config.js`. Never hardcode values in experiment files — always add a constant to config.

### Current Experiment Parameters

**Phase 1 (Social Learning)**

| Key | Value | Notes |
|---|---|---|
| `TOTAL_FACES` | `40` | Unique Phase 1 face identities |
| `EXPOSURES_PER_FACE` | `12` | On-screen appearances per face; also = block count |
| `FACES_PER_TRIAL` | `4` | Faces shown per trial panel |
| `FACE_COLOR_SPLIT.equal` | `{red: 20, blue: 20}` | — |
| `FACE_COLOR_SPLIT.'majority-minority'` | `{majority: 32, minority: 8}` | Minority good-rate rounds to 75% (6/8) |
| `GOOD_BAD_RATIO` | `[0.7, 0.3]` (both groups) | 70% good, 30% bad |
| `GOOD_PERSON_PROBS` | `{reward: 0.9, punishment: 0.1}` | — |
| `BAD_PERSON_PROBS` | `{reward: 0.5, punishment: 0.5}` | — |
| `REWARD_VALUE` | `1` | Points per reward |
| `PUNISHMENT_VALUE` | `-5` | Points per punishment |

**Phase 2 (Generalization Test)**

| Key | Value | Notes |
|---|---|---|
| `TOTAL_NOVEL_FACES` | `120` | Pool of novel face identities (60 per color) |
| `PHASE2_TOTAL_TRIALS` | `20` | Faces shown per session; 3 questions each = 60 slider responses |
| `PHASE2_EXPOSURE_RATIOS` | equal: 50/50, majority-red: 80/20, majority-blue: 20/80 | — |

**Global flags**

| Key | Value | Notes |
|---|---|---|
| `PILOT_MODE` | `true` | Forces Phase 2 exposure to Equal (6 active conditions) |
| `DISABLE_DATA_SAVING` | `false` | Set to `true` to suppress all Firebase writes |
| `POINTS_TO_DOLLARS` | `0.01` | 100 points = $1 bonus |

Full codebook at `CONFIG.CONDITION_CODES`. Pilot canonical codes: `EXE`, `ECE`, `RXE`, `RCE`, `BXE`, `BCE`. See RESEARCH_DESIGN.md §2 for the full table and code scheme.

## 5. Building & Deployment

### Build

```bash
npm run build  # Outputs to dist/
```

Webpack bundles JS/CSS and copies `stimuli/` and `assets/` into `dist/` via `CopyWebpackPlugin`. The `dist/` directory is cleaned on each build.

### Deploy to GitHub Pages

```bash
npm run build

git stash                              # Stash uncommitted changes
git checkout gh-pages
cp -rf dist/. .                        # Overwrite gh-pages root with new build
git restore --staged docs/             # Unstage docs/ (keep research docs out of gh-pages)
git add -A
git commit -m "Deploy: <description>"
git push demo gh-pages                 # Deploy to primary remote
git push origin gh-pages               # Deploy to backup remote
git checkout -f master                 # Return to dev branch (force flag handles .claude/ conflict)
git stash pop                          # Restore stashed changes
```

> **Known issue:** `git checkout master` fails if `.claude/settings.local.json` exists in the gh-pages working tree. Always use `git checkout -f master` after deploying.

## 6. Firebase

### Configuration

Credentials live in `src/utils/config.js → CONFIG.FIREBASE_CONFIG`. The project uses anonymous authentication — no login required from participants.

- **Project:** `socialexposuretheory2026`
- **Database URL:** `https://socialexposuretheory2026-default-rtdb.firebaseio.com`
- **Console:** https://console.firebase.google.com → socialexposuretheory2026

### Enabling / Disabling Data Saving

```javascript
// src/utils/config.js
DISABLE_DATA_SAVING: false  // Set to true to suppress all Firebase writes during testing
```

### Security Rules

```json
{
  "rules": {
    "participants": {
      "$participant_id": {
        ".read": false,
        ".write": "auth != null && !data.exists()"
      }
    }
  }
}
```

Write-once rule: a participant can only write their data once. Prevents accidental overwrites from refreshes or restarts.

### Participant ID Strategy

1. **Prolific PID** (primary): used as the Firebase key (`participants/{prolific_pid}/`)
2. **Internal ID** (`internal_XXXXX`): generated as fallback if Prolific PID is absent; always stored in `metadata.internal_id` regardless

### Firebase Database Schema

```
participants/
  {participant_id}/
    metadata:    { internal_id, prolific_pid, study_id, session_id,
                   condition_code, condition, majority_group,
                   p1_type, p2_exposure, pilot_mode, timestamp, debug_mode }
    demographics: { age, gender, race_ethnicity, education, ses_ladder,
                    political_orientation, employment_status, primary_language,
                    english_proficiency, geographic_location, vision_correction,
                    color_blind, device_type }
    summary:     { phase1_score, phase2_score, total_score,
                   phase1_trials_count, phase2_trials_count, phase3_trials_count }
    trials:
      phase1: [ { task, block, trial_in_block, trial_number, faces_in_trial,
                  chosen_face_id, chosen_face_color, chosen_face_is_good,
                  outcome, total_score, rt } ]
      phase2: [ { task,  face_id, face_color, face_is_good, face_trial_index,
                  image_path, <task-specific fields>, rt }
                 # task = 'phase2_slider', 'phase2_probability', or 'phase2_confidence'
                 # slider adds: slider_rating, outcome, phase2_score
                 # probability adds: probability_punishment
                 # confidence adds: confidence_rating ]
      phase3: [ { task, face_id, face_color, face_is_good,
                  probability_punishment, rt } ]
    surveys:
      technical_check: { images_loaded, technical_difficulties,
                         technical_difficulties_details }
      user_feedback:   { clarity_rating, confusion_phase, confusion_phase1_details,
                         confusion_other_phases, length_rating, suggestions }
```

### Data Export

**Step 1 — Download from Firebase:**
Firebase Console → Realtime Database → `participants` node → ⋮ menu → Export JSON → save as `data/firebase_export.json`

**Step 2 — Convert to CSV:**

```bash
pip install pandas
python scripts/firebase_to_csv.py
```

```r
install.packages(c("jsonlite", "dplyr", "tidyr", "purrr"))
source("scripts/firebase_to_csv.R")
export_all()
```

**Output files** in `data/csv_exports/`:

| File | Content |
|---|---|
| `participants.csv` | One row per participant (metadata + summary) |
| `demographics.csv` | Demographics responses |
| `phase1_trials.csv` | All Phase 1 trials, long format |
| `phase2_trials.csv` | All Phase 2 trials (all 3 task types), long format |
| `phase3_trials.csv` | All Phase 3 ratings, long format |
| `surveys.csv` | Technical check + user feedback |

Filter debug/test participants before analysis: `debug_mode == false`.

## 7. Troubleshooting

| Issue | Likely cause | Fix |
|---|---|---|
| Webpack compilation error | Stale cache or missing package | `npm install`; or delete `node_modules` + `package-lock.json` and reinstall |
| Firebase permission error | Anonymous auth disabled or wrong security rules | Firebase Console → Authentication → enable Anonymous; check rules match §6 above |
| Image loading failure | Missing images or webpack not copying stimuli | Verify 320 images in `stimuli/faces/`; confirm `CopyWebpackPlugin` in `webpack.config.js` includes `stimuli/` |
| "Sample size exceeds set size" | Sampling code error in majority condition | Handled automatically by `sampleWithReplacement` fallback in `helpers.js → generatePhase2Trials` |
| SurveyJS "Invalid expression: 'true'" | `choicesEnableIf: true` in survey JSON | Remove the property; SurveyJS auto-enables search for 10+ options |
| `git checkout master` fails after deploy | `.claude/settings.local.json` conflict | Use `git checkout -f master` |
| Data not saving | `DISABLE_DATA_SAVING: true` or credentials wrong | Check `config.js`; verify Firebase credentials; check browser console for errors |

- [ ] Condition URLs generated and documented for Prolific study setup
